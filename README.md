# CrossSight

> **Fictional sample pack for demo only.** Project Atlas and every contract clause, blueprint, photo and certificate in this repo are invented for this demo. There is no real company or real data anywhere in it.

## What CrossSight is

CrossSight is an **audit engine**, not a chatbot, a document search box or a photo describer. It runs **one audit**: it cross-checks a project's **contract**, its **blueprint** and its **site photo**, finds where the three disagree, and proves each disagreement to the exact clause, blueprint region or photo region. Each finding becomes an action that a person approves, and a fix is verified against a new photo.

The demo order is always: **masks → cross-check → finding → action → verification → diagram.**

In the sample pack, Contract §4.2 requires fire-rated cable Type A for riser run R-1. Blueprint Sheet 7 shows Type B, and Site Photo 12 shows Type C installed. That is finding **CS-001** (High). The expired inspection certificate is **CS-002** (Medium).

Findings are structured JSON with citations. Low confidence always reads "needs human review". CrossSight flags risks for a person to review. It never approves, dismisses or closes anything itself, and it states no cost figures, no safety verdicts and no legal advice.

## How to run / reproduce the demo

Requires Node.js 18.18 or newer.

**1. Install**

```bash
npm install
```

**2. Mock mode (default).** Mock mode needs no key and makes no Meta call. To set it explicitly, copy `.env.example` to `.env.local` and leave `META_MODE=mock`:

```bash
cp .env.example .env.local
```

**3. Run it.** Either the development server:

```bash
npm run dev
```

or the production build, which is what to record from:

```bash
npm run build
npm run start
```

Open http://localhost:3000.

**4. Check the code (optional).**

```bash
npm run typecheck
```

**5. Before recording, click "Reset demo"** (bottom of the sidebar). It clears this browser's saved demo state, so every step starts empty.

**6. Walk the demo, in order.** Click **Run audit** on Upload, then follow the sidebar.

## What is mock, and what is still pending

**Everything you see runs in mock mode.** No Meta API call is made.

- **Mock:** the SAM masks and region boxes, the two findings, the fix-photo check, the portfolio, the ledger entries, the audit packet and the diagram. They come from fixed data in `lib/mock.ts` and `lib/mock-portfolio.ts`, and from the demo session saved in your browser.
- **Ledger hashes:** a small non-cryptographic function that illustrates a tamper-evident chain. It is not a cryptographic proof system.
- **Diagram and living twin:** the diagram is a fixed in-app drawing and the twin is three still images. Neither is generated by a model, and the twin is not a live site feed or video.
- **Still pending, not wired:**
  - **SAM 3.1** (live masks). A first live check has not passed yet.
  - **Muse Spark** (live cross-check).
  - **Muse Image** (live corrected detail).

When they are wired, **all three will be called only from `lib/meta.ts`**. It is the only file allowed to talk to the Meta Model API, and every result will be cached by a hash of its input. Setting `META_MODE=live` today throws "not wired" so that no live call can happen by accident.

The API key goes in `.env.local` as `META_API_KEY`, read only on the server. **`.env.local` is gitignored and is never committed**, and neither are `.cache`, `node_modules` or `.next`. The fallback plan for the demo is live, then cached, then a recorded video.

## Guardrails

CrossSight flags risks for an engineer, lawyer or safety officer to review. It gives no legal advice, no safety verdict and no invented cost figures, and it never approves or closes anything on its own. A person approves every action and closes every finding.
